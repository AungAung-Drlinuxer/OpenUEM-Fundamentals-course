# Module 07 — လေ့ကျင့်ခန်းများ

လေ့ကျင့်ခန်း ခြောက်ခုလုံးကို `lab.py` တွင် အကောင်အထည်ဖော်ထားသည်။ တစ်ခုချင်း run ရန် function အမည်ကို ခေါ်နိုင်သည်၊ သို့မဟုတ် ဖိုင်တစ်ခုလုံးကို run နိုင်သည်။

```bash
python3 modules/07_device_management/lab.py
```

လေ့ကျင့်ခန်း တစ်ခုစီတွင် fixture data ကို ကုဒ်ဖြင့် ဖတ်ပြီး ရလဒ်ကို တွက်ချက်ရသည်။ အဖြေကို မကြည့်မီ ကိုယ်တိုင် တွက်ကြည့်ရန် အကြံပြုသည်။

## Exercise 1 — Inventory completeness ကို တွက်ချက်ခြင်း

Endpoint လေးလုံး၏ inventory report တွင် မည်သည့် tab များ ပါဝင်သည် ဆိုသည့် fixture တစ်ခု ပေးထားသည်။ Inventory tab စုစုပေါင်း ဆယ်ခုကို အခြေခံပြီး endpoint တစ်ခုစီအတွက် —

1. ရရှိထားသော tab အရေအတွက်ကို ရှာပါ။
2. ရာခိုင်နှုန်း အမှတ်ကို တွက်ပါ (integer သို့ ဝိုင်းပါ)။
3. အမှတ်အလိုက် အခြေအနေ သတ်မှတ်ပါ — 95 နှင့် အထက် `complete`၊ 80 နှင့် အထက် `partial`၊ ကျန်သည်မှာ `incomplete`။
4. လိုနေသော tab များကို စာရင်းပြပါ။

Endpoint အမည်အလိုက် စီပြီး ရလဒ်ကို ပြပါ။ နောက်ဆုံးတွင် အခြေအနေ တစ်မျိုးစီ၏ အရေအတွက်ကို စုစည်းပြပါ။ ရလဒ်ကို assertion ဖြင့် စစ်ဆေးပါ။

## Exercise 2 — OS အလိုက် package manager ရွေးချယ်ခြင်း

Endpoint ခြောက်လုံး၏ OS family နှင့် version ကို ပေးထားသည်။ OS family တစ်ခုစီအတွက် သက်ဆိုင်ရာ deployment engine ကို ရွေးပါ —

- `windows` → WinGet
- `linux` → Flatpak
- `macos` → HomeBrew
- အခြား family → ပံ့ပိုးမှု မရှိခြင်း

Endpoint တစ်ခုစီအတွက် အမည်၊ OS family၊ version နှင့် engine ကို စီပြပါ။ ပံ့ပိုးမှု ရရှိသော endpoint အရေအတွက်ကို စုစုပေါင်းနှင့် နှိုင်းယှဉ်ပြပါ။ Engine မရှိသော family အတွက် ရလဒ်သည် ဗလာ ဖြစ်ကြောင်း assertion ဖြင့် စစ်ပါ။

## Exercise 3 — Offline agent အတွက် deployment queue ပုံဖော်ခြင်း

Deployment request ငါးခု ပေးထားသည်။ Request တစ်ခုစီတွင် endpoint၊ package နှင့် agent အွန်လိုင်း ရှိ မရှိ ပါဝင်သည်။

1. ပထမ အဆင့်တွင် request တစ်ခုစီကို စစ်ပါ။ Agent အွန်လိုင်း ရှိပါက `delivered`၊ မရှိပါက `queued` ဟု မှတ်ပါ။
2. ဒုတိယ အဆင့်တွင် endpoint နှစ်ခု ပြန်လာ၍ ချိတ်ဆက်သည်ဟု သတ်မှတ်ပါ။ ထို endpoint များ၏ တန်းစီနေသော request ကို `delivered` သို့ ပြောင်းပါ။
3. ကျန်ရှိနေသော `queued` request ကို ပြပါ။
4. နောက်ဆုံး အရေအတွက် နှစ်မျိုးကို စုစည်းပြပါ။

အစီအစဉ်သည် အမြဲတူညီသော ရလဒ် ရရှိရမည်။ Endpoint အမည်အလိုက် စီပါ။

## Exercise 4 — Profile task များကို စစ်ဆေးခြင်း

Profile တစ်ခုတွင် task ခုနစ်ခု ပါဝင်သည်။ Task တစ်ခုစီတွင် `id`၊ `family`၊ `platform` နှင့် `name` ရှိသည်။ အောက်ပါ စည်းမျဉ်းများဖြင့် လက်ခံ သို့မဟုတ် ငြင်းပယ်ပါ —

- `registry_key`၊ `powershell_script` နှင့် `msi_package` သည် Windows တွင်သာ ရနိုင်သည်။
- `shell_script` သည် Linux နှင့် macOS တွင်သာ ရနိုင်သည်။
- `install_package`၊ `uninstall_package`၊ `local_user` နှင့် `local_group` သည် platform အားလုံးတွင် ရနိုင်သည်။
- မသိသော family ကို ငြင်းပယ်ပါ။
- အမည် ဗလာဖြစ်နေသော task ကို ငြင်းပယ်ပါ။

Task တစ်ခုစီအတွက် `ACCEPT` သို့မဟုတ် `REJECT` နှင့် ငြင်းပယ်သည့် အကြောင်းရင်းကို ပြပါ။ လက်ခံသည့် နှင့် ငြင်းပယ်သည့် အရေအတွက်ကို စုစည်းပါ။

## Exercise 5 — Tag filter ဖြင့် ပစ်မှတ် ရွေးချယ်ခြင်း

Agent လေးလုံးတွင် tag များ တပ်ထားသည်။ Filter တစ်ခုတွင် tag စာရင်းနှင့် mode (`all` သို့မဟုတ် `any`) ပါဝင်သည်။

- `all` mode တွင် tag အားလုံး ပါဝင်သော agent ကို ရွေးပါ။
- `any` mode တွင် tag တစ်ခုခု ပါဝင်သော agent ကို ရွေးပါ။

Filter နှစ်ခုကို တွက်ပါ — `finance` နှင့် `lab` ကို `all` mode ဖြင့်၊ ထို့နောက် `finance` နှင့် `kiosk` ကို `any` mode ဖြင့်။ ရွေးချယ်ခံရသော agent အမည်များကို အက္ခရာ အစဉ်အလိုက် စီပြီး ပြပါ။ Mode တစ်ခုစီတွင် မည်မျှ ကျန်ခဲ့သည်ကို တွက်ပြပါ။

## Exercise 6 — Health flag များကို စုစည်းခြင်း

Endpoint လေးလုံး၏ အခြေအနေ လေးမျိုး ပေးထားသည် — နောက်ဆုံး report မှ ကုန်ဆုံးသော မိနစ်၊ antivirus ဖွင့်ထားခြင်း၊ စောင့်ဆိုင်းနေသော update အရေအတွက် နှင့် disk လွတ်နေရာ ရာခိုင်နှုန်း။ အောက်ပါ စည်းမျဉ်းများဖြင့် flag သတ်မှတ်ပါ —

- မိနစ် 1440 ကျော်လျှင် `not_reporting`
- antivirus ပိတ်ထားလျှင် `antivirus_disabled`
- update တစ်ခုနှင့် အထက် စောင့်ဆိုင်းနေလျှင် `updates_pending`
- disk လွတ်နေရာ 10 ရာခိုင်နှုန်းအောက် ဖြစ်လျှင် `low_disk`

Endpoint တစ်ခုစီ၏ flag များကို ပြပါ (flag မရှိပါက `healthy`)။ ထို့နောက် flag တစ်မျိုးစီ၏ အရေအတွက်ကို အက္ခရာ အစဉ်အလိုက် စီပြီး ပြပါ။ နောက်ဆုံးတွင် ကျန်းမာသော endpoint အရေအတွက်ကို စုစုပေါင်းနှင့် နှိုင်းယှဉ်ပြပါ။
