# Module 09 — လေ့ကျင့်ခန်းများ

လေ့ကျင့်ခန်း ခြောက်ခုလုံးကို `lab.py` တွင် တည်ဆောက်ရမည်။ function တစ်ခုစီသည်
မိမိ လုပ်ငန်း ပြီးဆုံးလျှင် `[OK] exercise_N — <ဖော်ပြချက်>` ကို print ရမည်။
ဖိုင် အဆုံးတွင် `[PASS] All 6/6 exercises passed successfully.` ကို print ရမည်။
ကွန်ရက် မ လိုအပ်၊ third-party package မ လိုအပ်၊ deterministic ဖြစ်ရမည်။

## Exercise 1 — Report အတန်း စစ်ထုတ်ခြင်း

Agent ခြောက်ခု၏ fixture ကို သတ်မှတ်ရမည်။ ချန်လှပ်မည့် အချက်များမှာ
အမည်၊ site၊ platform၊ state၊ နောက်ဆုံး report မှ နာရီ အရေအတွက်၊
antivirus အခြေအနေ နှင့် pending update အရေအတွက် ဖြစ်သည်။

လုပ်ဆောင်ရမည့် အလုပ်များ —

1. agents view အတွက် site `yangon` နှင့် state `Enabled` ဖြစ်သည့် အတန်းများကို
   စစ်ထုတ်ပြီး အမည် အလိုက် စီရမည်။
2. computers view အတွက် platform သည် `windows` သို့မဟုတ် `linux` ဖြစ်ပြီး
   နောက်ဆုံး report မှ ၂၄ နာရီ အတွင်း ဖြစ်သည့် အတန်းများကို စစ်ထုတ်ရမည်။
   `Waiting for admission` state ရှိ အတန်းများကို ထည့်မ ရ — ထို agent များသည်
   chart များတွင် မ ပါဝင်ပါ။
3. security view အတွက် antivirus `disabled` ဖြစ်သည့် အတန်းများကို စစ်ထုတ်ရမည်။
4. software view အတွက် install count သည် ၃ နှင့် အထက် ဖြစ်သည့် software
   အတန်းများကို စစ်ထုတ်ရမည်။

စစ်ထုတ်မှု တစ်ခုစီအတွက် `rows=ကို/စုစုပေါင်း` နှင့် ကျန်ရှိသည့် အမည်များကို
အမည် အလိုက် စီပြီး print ရမည်။ filter သတ်မှတ်ချက် တစ်ခုစီကို dictionary
အဖြစ် သိမ်းပြီး export လုပ်သည့် ရလဒ်နှင့် တွဲဖက် ပြန်ထုတ်နိုင်ရမည် —
filter ထိန်းသိမ်းမှုကို ဤ နည်းဖြင့် စစ်ဆေးသည်။

နမူနာ output လိုင်း —

```text
[report] agents    filter=site:yangon,state:Enabled      rows=3/6 -> lnx-003, lnx-006, ws-001
```

## Exercise 2 — Dashboard alert ဦးစားပေး သတ်မှတ်ခြင်း

Dashboard ၏ ကဏ္ဍ သုံးခုအတွက် fixture ကို သတ်မှတ်ရမည်။

- Red — `agents_not_reporting`, `antivirus_disabled`, `pending_updates`,
  `agent_app_updates` (အရေအတွက် နှင့် severity ပါဝင်သည်)
- Green — user, app, tag အရေအတွက်
- Blue — console, NATS, worker, OCSP, PostgreSQL အခြေအနေ

လုပ်ဆောင်ရမည့် အလုပ်များ —

1. severity အလိုက် အလေးချိန် သတ်မှတ်ရမည် — `critical` သည် ပထမ၊
   `high` ဒုတိယ၊ `medium` တတိယ၊ `low` စတုတ္ထ။ အလေးချိန် တူလျှင်
   အရေအတွက် များသည့် အရာကို ရှေးရှု စီရမည်။ နှစ်ခုလုံး တူလျှင်
   အမည် အလိုက် စီရမည်။
2. Red ကဏ္ဍ အတွင်းရှိ အရာများကို ဦးစားပေး စာရင်း အဖြစ် print ရမည်။
3. Green ကဏ္ဍ နှင့် Blue ကဏ္ဍ သည် alert စာရင်းထဲ မ ပါဝင်ရ။ ထို အချက်ကို
   assertion ဖြင့် စစ်ရမည်။
4. Refresh ကာလ (၅ မိနစ် = ၃၀၀ စက္ကန့်) မှ ဒေတာ၏ အများဆုံး
   နောက်ကျနိုင်သည့် အချိန်ကို တွက်ပြီး print ရမည်။

## Exercise 3 — အလွှာလိုက် ဆက်သွယ်မှု အကဲဖြတ်ခြင်း

အလွှာ ငါးခု၏ အစဉ်ကို သတ်မှတ်ရမည် —

1. `endpoint→nats:4433`
2. `nats→agent-worker`
3. `agent-worker→postgres:5432`
4. `console:1323/1324`
5. `console→ocsp:8000`

Fixture အဖြစ် အခြေအနေ လေးမျိုး ပေးထားသည် — အလွှာ တိုင်း အောင်မြင်၊
အလွှာ ၁ ကျ၊ အလွှာ ၃ ကျ၊ အလွှာ ၅ ကျ။

လုပ်ဆောင်ရမည့် အလုပ်များ —

1. အလွှာ တစ်ခုချင်း အစဉ်လိုက် အကဲဖြတ်ရမည်။ ပထမဆုံး ကျသည့် အလွှာတွင်
   ရပ်ရမည်။
2. မ စမ်းသပ်ရသေး သည့် အောက်လွှာများကို `not tested` အဖြစ် သတ်မှတ်ရမည်။
3. အခြေအနေ တစ်ခုစီအတွက် `first_failure`, `verdict` နှင့် အလွှာ တစ်ခုချင်း၏
   အခြေအနေ ကို print ရမည်။
4. အောက်လွှာများကို "ကောင်းသည်" ဟု မ သတ်မှတ်ကြောင်း assertion ဖြင့်
   စစ်ရမည်။

## Exercise 4 — Log ခွဲခြားခြင်း

Agent log နှင့် component log မှ လိုင်း ဆယ်တစ်လိုင်း ပေးထားသည်။
ခွဲခြားမည့် အုပ်စုများမှာ `certificate`, `dns`, `auth`, `database`, `nats`,
`sftp`, `other` ဖြစ်သည်။

လုပ်ဆောင်ရမည့် အလုပ်များ —

1. စာလုံး အသေး အကြီး မ ခွဲဘဲ keyword ဖြင့် ခွဲခြားရမည်။
2. ဦးစားပေး အစဉ်ကို တိတိကျကျ သတ်မှတ်ရမည် — လိုင်း တစ်လိုင်းတွင် keyword
   နှစ်မျိုး ပါလျှင် ရှေးဦးစွာ စစ်သည့် အုပ်စုကို ယူရမည်။
3. အုပ်စု အလိုက် အရေအတွက်ကို အမည် အလိုက် စီပြီး print ရမည်။
4. လိုင်း တိုင်းတွင် အုပ်စု တစ်ခုတည်း ရရှိကြောင်း နှင့် စုစုပေါင်း လိုင်း
   အရေအတွက် ကိုက်ညီကြောင်း assertion ဖြင့် စစ်ရမည်။
5. ဖတ်ရမည့် အစဉ် (triage order) ကို သီးခြား စာရင်း အဖြစ် သတ်မှတ်ပြီး
   ၎င်း သည် တွေ့ရှိသည့် အုပ်စု အားလုံး ပါဝင်ကြောင်း စစ်ရမည်။

## Exercise 5 — MTTR နှင့် ပြန်ဖြစ်နှုန်း တွက်ချက်ခြင်း

ချို့ယွင်းမှု ခြောက်ခု၏ fixture ကို သတ်မှတ်ရမည်။ ချန်လှပ်မည့် အချက်များမှာ
အမှတ်၊ အကြောင်းရင်း၊ endpoint၊ ဖွင့်ချိန် နှင့် ပိတ်ချိန် ဖြစ်သည်။
အချိန် ပုံစံမှာ `YYYY-MM-DDTHH:MM:SS` ဖြစ်သည်။

လုပ်ဆောင်ရမည့် အလုပ်များ —

1. ချို့ယွင်းမှု တစ်ခုစီ၏ ကြာချိန်ကို မိနစ်ဖြင့် တွက်ရမည်။
2. အကြောင်းရင်း အလိုက် MTTR (ပျမ်းမျှ ပြန်လည် ကာလ) ကို တွက်ပြီး
   အကြောင်းရင်း အမည် အလိုက် စီ print ရမည်။
3. MTTR အမြင့်ဆုံး ချို့ယွင်းမှု တစ်ခုကို ရွေးပြီး print ရမည်။
4. endpoint အလိုက် ပြန်ဖြစ်နှုန်းကို တွက်ပြီး နှစ်ကြိမ် နှင့် အထက်
   ဖြစ်သည့် endpoint များကို print ရမည်။
5. စုစုပေါင်း MTTR ကို ဒသမ တစ်နေရာ အထိ print ရမည်။

လက်ရှိ အချိန်ကို မ သုံးရ။ တွက်ချက်မှု အားလုံးသည် fixture အချိန်များမှ
သာ ထွက်လာရမည်။

## Exercise 6 — Alert rule တိုက်ဆိုင်မှု

Rule သုံးခု နှင့် sample များ ပေးထားသည်။

| Rule | metric | ခြွင်းချက် | for_samples | severity |
|---|---|---|---|---|
| `agent_silent` | `hours_since_report` | `>` 24 | 2 | critical |
| `pending_updates_high` | `pending_updates` | `>=` 10 | 1 | high |
| `disk_low` | `free_disk_percent` | `<` 10 | 2 | high |

`for_samples` ဆိုသည်မှာ နောက်ဆုံး sample အရေအတွက် အားလုံး ခြွင်းချက် နှင့်
ကိုက်ညီမှ rule ကို ဖွင့်သည့် အဓိပ္ပာယ် ဖြစ်သည်။

လုပ်ဆောင်ရမည့် အလုပ်များ —

1. endpoint တစ်ခုစီ၏ sample များကို အချိန် အစဉ်လိုက် စစ်ရမည်။
2. rule တစ်ခုစီ တိုက်ဆိုင်မှုကို အကဲဖြတ်ပြီး ဖွင့်သည့် alert များကို
   severity အလိုက်၊ ထို နောက် endpoint အလိုက် စီ print ရမည်။
3. ဖွင့်သည့် alert အရေအတွက် နှင့် စစ်ဆေးသည့် ပေါင်း တိုက်ဆိုင်မှု အရေအတွက်
   ကို print ရမည်။
4. မ ဖွင့်သည့် ကိစ္စများကို အကြောင်းရင်း (`duration` သို့မဟုတ်
   `threshold`) အလိုက် ခွဲပြီး print ရမည်။
5. ဖွင့်သည့် alert စာရင်း တိတိကျကျ ကိုက်ညီကြောင်း assertion ဖြင့် စစ်ရမည်။

## တင်သွင်းခြင်း

```bash
python3 modules/09_reporting_troubleshooting/lab.py
```

အောင်မြင်ပါက exit code 0 နှင့် အောက်ပါ လိုင်း ပေါ်လာမည်။

```text
[PASS] All 6/6 exercises passed successfully.
```

ထို နောက် output ကို သုံးကြိမ် ပြန်လည် မောင်းနှင်ပြီး byte အလိုက်
တူညီ မ တူညီ စစ်ဆေးရမည်။
