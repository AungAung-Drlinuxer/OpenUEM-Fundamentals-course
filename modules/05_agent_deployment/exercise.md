# Module 05 — လေ့ကျင့်ခန်းများ

လေ့ကျင့်ခန်း ခြောက်ခုစီတွင် `modules/05_agent_deployment/lab.py` ၏ သက်ဆိုင်ရာ function ကို ဖြည့်စွက်ခြင်း သို့မဟုတ် ပြင်ဆင်ခြင်း ဖြစ်သည်။ exercise တစ်ခုစီကို သီးခြား run နိုင်သည်။

```bash
python3 -c "import importlib.util; spec=importlib.util.spec_from_file_location('lab','modules/05_agent_deployment/lab.py'); m=importlib.util.module_from_spec(spec); spec.loader.exec_module(m); m.exercise_1()"
```

`exercise_N` ကို ပြောင်းလဲ၍ exercise တစ်ခုချင်းစီကို စမ်းသပ်နိုင်သည်။ Exercise တစ်ခုပြီးတိုင်း သက်ဆိုင်ရာ `[OK]` စာကြောင်း ပေါ်ထွက်ရမည်။

## Exercise 1 — Silent-install flag line တည်ဆောက်ခြင်း

Windows endpoint များကို တစ်ပြိုင်နက် deploy လုပ်ရန် `openuem-agent-setup.exe` အတွက် argument line တစ်ကြောင်းကို dictionary တစ်ခုမှ တည်ဆောက်ရမည်။

လိုအပ်ချက်များ —

- ရလဒ်သည် `/VERYSILENT` ဖြင့် အစပြုရမည်။ ၎င်းသည် တစ်ကြိမ်တည်း ပါဝင်ရမည်။
- Flag အစီအစဉ်မှာ `cacert`, `cert`, `key`, `sftpcert`, `tenantid`, `siteid`, `server`, `sftp`, `vnc` ဖြစ်ရမည်။
- `server` မပါပါက `ValueError` ဖြင့် ငြင်းပယ်ရမည်။
- `tenantid` နှင့် `siteid` ကို အတူတကွ သာ လက်ခံရမည်။ တစ်ခုတည်း ပါဝင်ပါက `ValueError` ဖြင့် ငြင်းပယ်ရမည်။
- ပေးပို့ထားသည့် flag များသာ ရလဒ်တွင် ပါဝင်ရမည်။ မပေးပို့သည့် flag အတွက် တန်ဖိုး အလွတ် မထည့်ရ။
- `sftp` နှင့် `vnc` တန်ဖိုးများသည် 2022 နှင့် 1443 ဖြစ်ရမည်။

စစ်ဆေးသည့် အချက် — `/VERYSILENT` တစ်ကြိမ်တည်း ပါဝင်ခြင်း, `cacert` သည် `server` အရှေ့တွင် ရှိခြင်း, pair စည်းမျဉ်း နှင့် `server` မပါသည့် အခြေအနေ နှစ်ခုလုံး ငြင်းပယ်ခံရခြင်း။

## Exercise 2 — Platform အလိုက် certificate ဖိုင်စစ်ဆေးခြင်း

Agent တစ်ခုတွင် လိုအပ်သည့် ဖိုင် လေးခုမှာ `ca.cer`, `sftp.cer`, `agent.cer`, `agent.key` ဖြစ်သည်။ ပေးထားသည့် platform နှင့် ဖိုင်စာရင်းကို နှိုင်းယှဉ်ပြီး ပျက်ကွက်သည့် ဖိုင်များကို ရှာရမည်။

လိုအပ်ချက်များ —

- Platform တစ်ခုစီအတွက် မှန်ကန်သည့် folder ကို ပြန်ပေးရမည်။ Debian နှင့် Ubuntu အတွက် `/etc/openuem-agent/certificates`, RPM မိသားစုအတွက် `/etc/openuem-agent`, Windows အတွက် `C:\Program Files\OpenUEM Agent` ဖြစ်သည်။
- `missing` စာရင်းသည် ဖိုင် လေးခု၏ သတ်မှတ်ထားသည့် အစီအစဉ်အတိုင်း ဖြစ်ရမည်။
- မလိုအပ်သည့် ဖိုင်များကို `extra` စာရင်းတွင် အက္ခရာ အစီအစဉ်ဖြင့် ထည့်ရမည်။
- မသိသည့် platform အတွက် `ValueError` ဖြင့် ငြင်းပယ်ရမည်။
- ဖိုင် လေးခုလုံး ရှိသည့် အခြေအနေတွင် `missing` နှင့် `extra` နှစ်ခုလုံး အလွတ် ဖြစ်ရမည်။

စစ်ဆေးသည့် အချက် — Debian တွင် `sftp.cer` နှင့် `agent.key` ပျက်ကွက်သည့် အခြေအနေ, RPM တွင် မလိုအပ်သည့် `notes.txt` ပါဝင်သည့် အခြေအနေ, Windows တွင် `agent.cer` နှင့် `agent.key` ပျက်ကွက်သည့် အခြေအနေ။

## Exercise 3 — NATS endpoint နှင့် cluster စာရင်း စစ်ဆေးခြင်း

Agent သည် NATS server သို့ ချိတ်ဆက်ရန် `host:port` ပုံစံ လိုအပ်သည်။ Cluster တွင် server များ များပါက comma ဖြင့် ခွဲထားသည့် စာရင်းကို လက်ခံရမည်။

လိုအပ်ချက်များ —

- `host:port` ပုံစံ မှန်ကန်ပါက လက်ခံပြီး server အရေအတွက်ကို ပြန်ပေးရမည်။
- `://` ပါဝင်သည့် တန်ဖိုးကို ငြင်းပယ်ရမည်။ Scheme မလိုအပ်ပါ။
- Port မပါခြင်း, port တွင် ကိန်းဂဏန်း မဟုတ်သည့် စာလုံး ပါဝင်ခြင်း, port သည် 1 မှ 65535 ပြင်ပ ဖြစ်ခြင်းတို့ကို ငြင်းပယ်ရမည်။
- Comma ပြီးနောက် အလွတ် ပါဝင်ခြင်း နှင့် တန်ဖိုး လုံးဝ အလွတ် ဖြစ်ခြင်းတို့ကို ငြင်းပယ်ရမည်။
- Host တူညီသည့် server နှစ်ခု ပါဝင်ပါက ငြင်းပယ်ရမည်။
- ငြင်းပယ်သည့် အခြေအနေတိုင်းတွင် အကြောင်းရင်း စာသား ပါဝင်ရမည်။

စစ်ဆေးသည့် အချက် — မှန်ကန်သည့် တန်ဖိုး နှစ်ခုသာ လက်ခံခံရခြင်း, ကျန် ရှစ်ခု ငြင်းပယ်ခံရခြင်း, အကြောင်းရင်း စာသား တစ်ခုချင်းစီ မှန်ကန်ခြင်း။

## Exercise 4 — Report ကာလ တွက်ချက်ခြင်း

Report ကာလမှ တစ်ရက်လျှင် report အရေအတွက်, နောက် report ရောက်ရှိမည့် အချိန် နှင့် နောက်ကျမှု ကို တွက်ရမည်။

လိုအပ်ချက်များ —

- မိနစ် 60, 30, 15 အတွက် တစ်ရက်လျှင် report အရေအတွက်ကို တွက်ရမည်။
- Profile စစ်ဆေးမှုကာလ မိနစ် 30 အတွက် တစ်ရက်လျှင် အရေအတွက် နှင့် report တစ်ကြိမ်လျှင် profile စစ်ဆေးမှု အရေအတွက်ကို တွက်ရမည်။
- နောက်ဆုံး report အချိန် 09:10 နှင့် ကာလ မိနစ် 60 အတွက် နောက် report အချိန်ကို `HH:MM` ပုံစံဖြင့် ပြရမည်။
- `now` သည် 11:05 ဖြစ်ပါက နောက်ကျမှုကို မိနစ်ဖြင့် တွက်ပြီး အခြေအနေကို သတ်မှတ်ရမည်။
- အချိန်ကို စက်မှ မဖတ်ရ။ ပုံသေ တန်ဖိုးများဖြင့်သာ တွက်ရမည်။

စစ်ဆေးသည့် အချက် — report အရေအတွက် သုံးခု, profile အရေအတွက် 48, cycle တစ်ခုလျှင် 2, နောက်ကျမှု 55 မိနစ် နှင့် `overdue` အခြေအနေ။

## Exercise 5 — Log စာကြောင်း ခွဲခြားခြင်း

`openuem-log.txt` မှ စာကြောင်းများကို keyword အလိုက် အုပ်စုဖွဲ့ရမည်။ အုပ်စုများမှာ `certificate`, `connectivity`, `enrollment`, `sftp`, `vnc`, `configuration` နှင့် `unclassified` ဖြစ်သည်။

လိုအပ်ချက်များ —

- စည်းမျဉ်းစာရင်းကို အပေါ်မှ အောက်သို့ စစ်ပြီး ပထမဆုံး ကိုက်ညီသည့် အုပ်စုကို ယူရမည်။
- စာလုံးအသေးဖြင့် နှိုင်းယှဉ်ရမည်။
- မည်သည့် keyword နှင့်မျှ မကိုက်ညီပါက `unclassified` ဟု သတ်မှတ်ရမည်။
- အုပ်စုတစ်ခုစီ၏ အရေအတွက်ကို တွက်ပြီး အက္ခရာ အစီအစဉ်ဖြင့် ပြရမည်။
- ပုံသေ log ရှစ်ကြောင်းအတွက် အုပ်စု ခုနစ်မျိုး ထွက်ရမည်။

စစ်ဆေးသည့် အချက် — အုပ်စုတစ်ခုစီ၏ အရေအတွက်, `unclassified` နှစ်ခု, စည်းမျဉ်း အစီအစဉ်၏ သက်ရောက်မှု (`sftp: x509: certificate has expired` သည် `certificate` ဖြစ်ခြင်း)။

## Exercise 6 — Upgrade အန္တရာယ် အဆင့်သတ်မှတ်ခြင်း

Agent upgrade တစ်ခုအတွက် အကြောင်းရင်း ငါးခုကို အလေးချိန် ပေး၍ ရမှတ် တွက်ပြီး အန္တရာယ်ကို `low`, `medium`, `high` အဖြစ် သတ်မှတ်ရမည်။

လိုအပ်ချက်များ —

- အလေးချိန်များ — certificate သက်တမ်း ကုန်ဆုံးခြင်း 4, major version ခုန်ခြင်း 3, `openuem.ini` ကို ကိုယ်တိုင် ပြင်ထားခြင်း 2, offline agent ရှိခြင်း 2, rollback မစမ်းသပ်ထားခြင်း 1။
- ရမှတ် 5 နှင့် အထက် `high`, 2 နှင့် အထက် `medium`, ကျန်သည် `low` ဖြစ်သည်။
- အကြောင်းရင်း စာရင်းကို အက္ခရာ အစီအစဉ်ဖြင့် ပြရမည်။
- Offline agent ရှိပါက အရေအတွက်ကို အကြောင်းရင်း စာသားတွင် ထည့်ရမည်။
- အကြောင်းရင်း မရှိပါက ရမှတ် သုည နှင့် `low` ဖြစ်ရမည်။

စစ်ဆေးသည့် အခြေအနေ လေးခု — patch တိုးခြင်း (`low`, 0), offline agent နှစ်ခု နှင့် ini ပြင်ထားခြင်း (`medium`, 4), major version နှင့် ini ပြင်ထားခြင်း (`high`, 5), certificate ကုန်ဆုံးခြင်း နှင့် rollback မစမ်းသပ်ထားခြင်း (`high`, 5)။
